# 立面门窗检测与三维映射：实验记录及运行说明

记录日期：2026-09-30。二维结果来自 2026-09-29 的真实批次 `run_20260929_160455_549558`；三维结果使用 2026-09-30 重新保存的标定。

本阶段完成的是“已知建筑身份的立面照片 → 自动门窗检测 → 人工标定 → 三维墙面预测四边形”。项目原定的街景照片—建筑对象自动检索仍需继续开展，不能用本阶段结果替代建筑检索准确率实验。

## 1. 已完成的工作

1. 使用公开的 Grounding DINO Tiny 预训练权重，对 RGB 立面照片分别执行 `a window.` 和 `a door.` 提示推理。未在本数据集上重新训练模型。
2. 批量读取 `textures` 中的 17 张照片，一次加载本地模型，逐张保存原图检测框、JSON、CSV、待确认记录及全批汇总。一张失败会记录原因并继续处理其余图片。
3. 使用保持原像素尺寸的重叠分块，恢复原图坐标后进行去重。默认不额外推理整张大图，模型内部仍会计算不同尺度的特征。
4. 同一位置出现门/窗冲突时保留为 `ambiguous`，展示为黄色，保留原始候选和两类证据。该类不强行归入 CSV 的窗/门列，三维程序通过 JSON 继续读取它。
5. 根据照片文件名提取建筑编号，关联同编号 CityGML/OBJ，例如 `4959323_front.jpg` 关联建筑 `4959323`。这利用了数据集已有身份信息，并非根据照片外观自动识别建筑。
6. 对 `4959323_front` 人工确认墙面，点选照片与墙面对应位置，计算平面变换，再将检测框四角转换为源模型坐标系中的三维四边形。
7. 加入人工标定误差、照片区域、墙面边界、照片/模型内容指纹检查，保存三维 JSON、独立预测 OBJ/MTL 和可旋转预览。

51 张 `panoramas` 原始全景未作为这次检测输入，也未进行全景重建建筑。数据集已有 CityGML/OBJ，当前直接使用已有建筑几何。

## 2. 代码与参考项目的关系

参考项目：[chrise96/3D_building_reconstruction](https://github.com/chrise96/3D_building_reconstruction)。

| 内容 | 原参考项目 | 本次适配 |
|---|---|---|
| 二维模型 | Detectron2 Mask R-CNN，R50-FPN，`sky/window/door` | Grounding DINO Tiny，公开预训练权重，文字提示推理 |
| 二维权重 | 需要专用 `model_output/model.pth`；当前取得的参考材料没有该权重 | 读取本地已缓存的 `IDEA-Research/grounding-dino-tiny`，禁止运行时联网补下载 |
| 二维输出 | `texture_filename / bboxes_window / bboxes_door` | 保留三列接口，另加 JSON、待确认记录、批量汇总和映射清单 |
| 建筑关联 | 前一阶段的建筑编号及地理信息 | 照片文件名中的已知建筑编号 |
| 像素到三维 | 可见立面左右端点、固定图像覆盖高度等假设 | 人工对应点拟合单应矩阵：像素 XY → 墙面 UV（米）→ 模型 XYZ |
| 三维输出 | 向 CityGML 墙面写内环和 Window/Door opening | 预测四边形预览与 OBJ；尚未修改 CityGML 或生成墙体洞口 |

两个入口都是为当前数据新增的适配实现，没有直接导入参考 Stage 2/3 的 Python 函数。沿用了任务流程及部分输出字段约定，不能称为原作者实验的完整复现；使用的单应性变换、SVD 等也是通用几何方法，并非本项目新提出的算法。

二维推理不读取 `gt_masks`。三维人工标定窗口会显示已有 CityGML 的灰色洞口轮廓，帮助找对应点；它们不复制进预测集合，也不用于自动改变预测类别。因此不能把整个标定过程称为独立于已有标注的三维精度评测。

## 5. 仓库中的运行方法

### 文件与环境

两个入口放在仓库根目录：

- [detect_my_facade.py](../detect_my_facade.py)：二维批量检测。
- [map_facade_to_3d.py](../map_facade_to_3d.py)：逐图人工标定及三维映射。
- [tests/](../tests/)：去重、分块、批量错误恢复、几何与鼠标回调检查，不运行真实神经网络。

已验证的本机环境为 Python 3.8.20、PyTorch 2.4.1+cu124、Transformers 4.46.3、NumPy 1.24.4、Pillow 10.2.0、Matplotlib 3.7.5，交互窗口使用 TkAgg。其他环境需要自行核对兼容性；没有要求重新安装已可用的环境。

仓库副本的数据路径已经改为：

```python
DATASET_DIR = ROOT / "Drills/Texture2LoD3_dataset"
```

确认其中 `textures/` 是可打开的真实照片，`citygml/` 和 `obj/` 是已下载的模型。如果通过 Git LFS 获取数据，需要完整拉取相应内容，不能只保留 LFS 指针文件。

模型缓存不随这次代码提交上传。默认配置是：

```python
CACHE_DIR = ROOT / "model_cache"
```

若已下载的缓存放在仓库外，可把这一行改成自己的真实缓存路径。例如本机已有缓存位于上级工作目录，可以配置为：

```python
CACHE_DIR = ROOT.parent / "model_cache"
```

这里的目录应包含 `models--IDEA-Research--grounding-dino-tiny/refs/main` 及对应的 `snapshots/` 配置、分词文件和 `model.safetensors`。脚本只读本地快照；缺文件会报错，不会联网重新下载。

### 先运行二维检测

在 PyCharm 选择已经配置好的解释器，右键运行仓库根目录的 `detect_my_facade.py`，或在该目录执行：

```bash
python detect_my_facade.py
```

每次生成独立的 `my_results/batch_detection/run_.../`。先看 `batch_summary.csv`，再打开各照片目录的 `detections.png`。单张 JSON 保留确定框、待确认框和清理前候选；三列 CSV 只包含明确的窗/门。

`latest_run.json` 指向最近启动的批次。失败或中断后已完成的结果仍可查看，但当前不支持自动断点续跑；重新运行会重新处理全部照片。

### 再运行三维映射

检测完成后打开 `map_facade_to_3d.py`，设置：

```python
IMAGE_KEY = "4959323_front"
WALL_ID = None
RECALIBRATE = True
```

上传版本保留当前用于重新标定的 `RECALIBRATE=True` 设置。右键运行该文件，或执行：

```bash
python map_facade_to_3d.py
```

按以下顺序操作独立窗口：

1. 根据照片、建筑俯视图和墙面轮廓选择墙面，点击 `Use this wall`。
2. `Fit pair`：每组先点照片，再点墙面上的同一个物理位置，至少 4 对，建议 6～8 对，分散在上下左右。
3. `Check pair`：另选至少 1 对未参与拟合的位置，建议增加到 2～3 对并覆盖不同区域。
4. `Wall region`：只在照片上沿本墙面区域依次点至少 3 个角。拟合点和检查点应在该区域内，不能把另一面墙混入同一变换。
5. `Save + map`：默认要求拟合 RMSE ≤0.20 米、检查点最大误差 ≤0.30 米。失败原因在控制台显示；先核对点选，不为通过而直接放宽阈值。

工具栏可放大和平移；点选前先退出放大/平移模式。`Undo` 撤销当前模式的最近一步。标定成功后保存到 `my_results/calibrations/<image_key>.json`；满意后把 `RECALIBRATE=False` 即可复用。

每张照片、每个视角都需要自己的标定。照片或 CityGML 内容变化后，文件指纹检查会拒绝套用旧标定。新运行的二维结果可以复用同一张未变化照片的有效标定。

三维输出在当前批次的 `mapping_3d/<image_key>/`：

```text
predictions_3d.json       # 原框、三维四角、来源、未映射框及原因
predictions_preview.obj  # 仅预测四边形，不包含整栋楼
predictions_preview.mtl  # OBJ 配色，与 OBJ 保持同目录
mapping_preview.png     # 墙面展开图和建筑三维预览
calibration.json        # 本次标定副本
```

同批同图重新映射会更新上述三维结果；需要对比标定版本时先保留旧结果副本。

## 6. 当前问题与后续方向

| 问题 | 当前处理及下一步 |
|---|---|
| 小窗、遮挡或不完整窗漏检 | 已采用原像素重叠分块；缩放可能影响小目标，但不是已经证明的唯一原因，仍需同图对照与定量评价 |
| 同一开口同时预测门和窗 | 合并重复位置、保留两类证据并标为待确认；尚未自动确定正确类别 |
| 部分重复框或邻近目标可能合并不当 | 现有 IoU 与包含规则需要逐图检查，参数不能保证所有建筑都适用 |
| 原作者专用 Mask R-CNN 权重缺失 | 当前使用公开模型验证流程；是否在许可和数据条件满足后训练/微调专用模型，需要与导师确认 |
| 缺少可靠的检测精度评价 | 必须先解决标注图、照片和墙面身份及坐标配准，之后再统计漏检、误检和分类错误 |
| 三维标定依赖人工 | 当前只完成一个立面；继续完善多点检查和逐图标定，再研究自动对应关系 |
| 三维结果少于二维框 | 检查 `unmapped_detections` 区分区域越界与检测漏检，不能直接把被拒绝的框当成漏检 |
| 尚未实现建筑自动检索 | 当前建筑编号来自文件名；GPS、方向、可见性约束与候选建筑排序仍属于后续主线工作 |
| 尚未更新建筑实体 | 先核对位置和类别，再处理墙面开孔、门窗几何、语义写入及有效性检查 |
